# レジーム判定（Regime Detection）

## 概要

レジーム判定は、市場環境を分析して「買って良い週」「買うな週」を識別する機能です。

**重要**: これは価格予測ではありません。現在の市場状態を複数の指標で評価し、リスクが高い環境では新規買いを控えるルールベースの判定です。

## 3つの状態

### RISK_ON 🟢
- **意味**: 市場環境が良好
- **動作**: 通常どおりシグナルに従って売買
- **条件**: スコア +2 以上

### RISK_OFF 🔴
- **意味**: 市場環境が悪化、リスク回避推奨
- **動作**: 新規買いを停止（保有は継続）
- **条件**: スコア -2 以下

### NEUTRAL 🟡
- **意味**: 市場環境が中立的
- **動作**: 通常どおりシグナルに従って売買
- **条件**: スコア -1 〜 +1

## 判定ロジック

4つのフィルターでスコアを計算します（各 -1 〜 +1）：

### 1. Trendフィルタ（トレンド）
- **データ**: S&P500 (SPY)
- **計算**: 現在価格 vs 200週移動平均
- **スコア**:
  - +1: SPYが200週MA **上** → 上昇トレンド
  - -1: SPYが200週MA **下** → 下降トレンド

### 2. Volフィルタ（ボラティリティ）
- **データ**: VIX指数
- **計算**: 現在のVIX vs 閾値（デフォルト25）
- **スコア**:
  - -1: VIXが閾値 **超** → 市場が不安定
  - 0: VIXが閾値 **以下** → 市場が安定

### 3. Rateフィルタ（金利ショック）
- **データ**: 10年債金利 (TNX)
- **計算**: 4週間の変化 vs 閾値（デフォルト0.5%）
- **スコア**:
  - -1: 金利上昇が閾値 **超** → 金利ショック
  - 0: 金利変化が閾値 **以下** → 金利安定

### 4. FXフィルタ（為替ショック）
- **データ**: USD/JPY
- **計算**: 4週間の変化率 vs 閾値（デフォルト5%）
- **スコア**:
  - -1: 変化率が閾値 **超** → 為替ショック
  - 0: 変化率が閾値 **以下** → 為替安定

## 総合スコアの計算

```
総合スコア = Trend + Vol + Rate + FX
範囲: -4 〜 +1

例1: SPY上昇(+1) + VIX低(0) + 金利安定(0) + 為替安定(0) = +1 → NEUTRAL
例2: SPY上昇(+1) + VIX低(0) + 金利安定(0) + 為替安定(0) = +1 → NEUTRAL（閾値+2未満）
例3: SPY下降(-1) + VIX高(-1) + 金利ショック(-1) + 為替ショック(-1) = -4 → RISK_OFF
```

## 設定（config.yaml）

```yaml
regime:
  enabled: true                # レジーム判定を有効化
  threshold_on: 2              # RISK_ONになる閾値
  threshold_off: -2            # RISK_OFFになる閾値
  
  # データソースの有効化（取得失敗でも処理は継続）
  use_vix: true                # VIXを使用
  use_tnx: true                # 10年債金利を使用
  use_usdjpy: true             # USD/JPYを使用
  
  # パラメータ
  window_weeks_ma: 40          # 移動平均の週数（200日≒40週）
  vix_threshold: 25            # VIXの警戒閾値
  rate_shock_weeks: 4          # 金利急変判定の週数
  rate_shock_threshold: 0.5    # 金利変化の閾値
  fx_shock_weeks: 4            # 為替急変判定の週数
  fx_shock_threshold: 5.0      # 為替変化率の閾値（%）
```

## フェイルセーフ

### データ取得失敗時
- 個別データソース（VIX/TNX/USDJPY）が取得できない場合
  - そのフィルタのスコアは **0** として扱う
  - 処理は継続（システムは落ちない）
  - `reasons`に「data unavailable」と記録

### 全データソース失敗時
- 自動的に **NEUTRAL** として扱う
- 通常どおりシグナルに従って売買
- `reasons`に「Data fetch failed - failsafe to NEUTRAL」と記録

## 運用への影響

### RISK_OFF の週
1. **新規買い注文が生成されない**
   - `orders.csv`にBUY注文が含まれない
   - 資金は現金のまま保持

2. **既存保有は継続**
   - SELL注文は強制されない
   - 各銘柄の個別判断（テーマ強度低下など）でのみ売却

3. **既存のDD制御（-15%）と併用**
   - レジーム判定とは独立して動作
   - ポートフォリオ全体が-15%なら全売却（別の仕組み）

### RISK_ON / NEUTRAL の週
- 通常どおりシグナルに従って売買

## 使用上の注意

### ⚠️ これは予測ではありません
- 将来の市場を予測するものではない
- あくまで「現在の状態」を評価

### ⚠️ 最終判断はご自身で
- レジーム判定は補助ツール
- 投資判断は必ずご自身で行ってください

### ⚠️ 過去の性能は将来を保証しない
- バックテストなどは含まれていない
- 実運用での効果は未知数

## よくある質問

**Q: なぜ200週移動平均を使うのですか？**
A: 日次の200日移動平均は長期トレンドの指標として広く使われています。週次なので40週≒200日としています。

**Q: 閾値は変更できますか？**
A: はい、`config.yaml`で自由に調整できます。ただし、バックテストなしで変更すると予期しない動作になる可能性があります。

**Q: データが取得できない場合はどうなりますか？**
A: フェイルセーフとしてNEUTRALになり、通常運用を継続します。

**Q: RISK_OFFでも売却しないのはなぜですか？**
A: 市場環境が悪いからといって保有株を投げ売りするのは最適ではない場合があるためです。新規買いを控えることでリスクを管理します。

**Q: 機械学習は使っていますか？**
A: いいえ、完全にルールベースです。予測モデルは使用していません。
